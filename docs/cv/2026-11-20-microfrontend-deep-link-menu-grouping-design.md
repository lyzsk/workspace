# 微前端深链、加载体验与菜单虚拟分组设计

> 日期：2026-11-20
> 范围：workspace 宿主、EAP/ws-test 两个现有子应用、菜单管理页、下载模板验收
> 已确认：保留当前 qiankun 单轨、AuthBridge、JWT 刷新、应用角色边界、真实仪表盘和现有端口

## 1. 目标

1. 子应用内部路由可通过宿主地址恢复，刷新后停留在原页面。
2. 宿主菜单与子应用内部路由双向同步，不重复挂载、不形成导航回环。
3. 宿主处理 ready/error，提供渲染超时兜底和延迟骨架。
4. 菜单管理页按应用展示虚拟分组；角色管理继续按应用隔离授权。
5. 下载模板经过真实构建和当前宿主联调后，再决定是否作为团队标准。

## 2. 非目标

- 不引入 single-spa 与 qiankun 双加载器。
- 不修改当前认证、HTTP 刷新重试、仪表盘实现。
- 不恢复 `<app>:access` 或 `apps:<app>:access` 授权模型。
- 不删除 `sys_role.app_id`，不合并跨应用角色授权。
- 不使用下载包的 5174/61125 端口。
- 本轮不重排宿主侧边栏，不实施同事文档中的应用入口一级化和角色全量树。

## 3. 宿主路由契约

### 3.1 路径定义

- `basePath`：宿主应用根路径，例如 `/apps/eap-tool-service`。
- `initialPath`：子应用内部路径，例如 `/caliber`，不包含 `basePath`。
- `app.route.changed.path`：子应用内部路径，必须以 `/` 开头，不包含 `basePath`。
- `host.route.changed.path`：与 `initialPath` 使用同一内部路径口径。

新增纯函数负责路径规范化和拼接：

- 从宿主 `pathMatch` 参数生成内部路径。
- 拒绝空路径时产生重复斜杠。
- 子应用误传完整宿主路径时去除重复 `basePath`。
- 保留 query 与 hash。
- 目标宿主路径与当前路径相同时不导航。

### 3.2 挂载与刷新

1. `MicroFrontendHost` 从当前路由计算 `initialPath`。
2. `utils/qiankun.ts` 将其透传到子应用 props。
3. 子应用创建路由或完成认证后进入该内部路径。
4. 挂载完成后重新读取当前宿主路径；若加载期间发生变化，补发最新 `host.route.changed`。

### 3.3 双向同步

- 子应用发 `app.route.changed`：宿主更新标题并 `router.replace(basePath + internalPath)`。
- 宿主 `pathMatch` 变化：向当前活动子应用发 `host.route.changed`，不重新挂载。
- 子应用接收后先比较内部当前路径，相同则忽略。
- 离开应用、会话切换和组件卸载后，旧事件不得影响新实例。

## 4. 加载与错误处理

### 4.1 延迟骨架

- 加载状态立即更新，骨架在 300ms 后显示。
- 快速加载不显示骨架，避免整页灰色遮罩和闪烁。
- 只有最新 routeSequence 可以停止骨架。
- 卸载和重新进入时清理骨架定时器。

### 4.2 ready/error

- 子应用首帧完成后发 `app.ready`。
- 宿主在挂载后启动 10 秒 watchdog；收到 ready、卸载或重新进入时清除。
- 超时必须更新宿主本地错误状态并提供重试，不只发送无人消费的宿主事件。
- `app.error` 显示子应用异常；`app.auth.failed` 显示权限错误提示。
- 当前挂载异常处理、会话刷新和统一退出逻辑保持不变。

## 5. 现有子应用适配

### EAP

- `MicroProps` 增加 `initialPath` 和路径契约。
- 工作区认证完成后跳转到 initialPath，而非固定首页。
- 监听 `host.route.changed`，内部路径相同则不重复导航。
- 首帧完成后发送 `app.ready`。
- 卸载时移除宿主事件监听，保留当前挂载节点修复。

### ws-test

- 增加相同的 initialPath、host.route.changed 和 ready 支持。
- 保留当前本地登录换取业务 token 的流程。
- 卸载时同时清理路由监听与宿主事件监听。

## 6. 菜单管理虚拟分组

### 6.1 后端

- `SysMenuTreeVO` 增加 `appCode`，`toVO` 从实体回填。
- 菜单管理专用全量树返回所有应用菜单。
- 保留按 appCode 查询的重载，角色管理继续使用应用内菜单。
- 不修改 `currentUserTree`、`appendRegisteredApps`、`MenuMapper.selectByUserId`。

### 6.2 前端

- `MenuNode` 增加可选 `appCode`。
- 新增菜单分组工具，只包含虚拟分组、跨应用父节点提升和虚拟 ID 判断。
- 不复制下载工具中的旧访问按钮自动授权逻辑。
- 菜单管理页显示虚拟应用行；虚拟行不可编辑、删除，只可作为新增入口。
- 编辑和创建时，父节点候选限制在当前 `form.appCode`。
- 子应用 MENU 的 component 为空；宿主 MENU 继续要求 component。
- 保留菜单列表请求版本号和表单草稿。

### 6.3 角色边界

- 角色管理页和 `query.appCode` 保持不变。
- 角色编辑只加载当前应用菜单。
- 虚拟应用 ID 不进入任何角色授权请求。
- 不实施跨应用统一角色树。

## 7. 模板验收

1. 将模板作为独立骨架处理，不覆盖 workspace-ui。
2. 在干净目录执行冻结依赖安装、类型检查和生产构建。
3. 构建所需 qiankun 插件失败时应终止构建，不静默降级。
4. 使用当前宿主注册测试应用，验证真实登录、刷新、深链、主题、退出、401/403、重复挂载和弹层。
5. 两个现有子应用验证通过后，再以相同用例验收模板。
6. 验收通过前模板只标记为候选骨架。

## 8. 测试与验收

### 自动化

- 路径规范化、basePath 去重、query/hash、路由回环保留测试。
- 菜单虚拟分组、跨应用父节点、虚拟 ID 过滤测试。
- 后端菜单 VO/appCode 与全量/单应用树测试。
- workspace-ui 全量测试和生产构建。
- EAP/ws-test 独立构建与微前端构建。
- 后端相关模块测试。

### 人工浏览器

1. 进入两个现有子应用的非默认页面并刷新，恢复相同页面。
2. 子应用内部导航只更新地址，不重新挂载。
3. 宿主子菜单导航不整页刷新，子应用跟随。
4. 快速进入不显示骨架；慢加载显示骨架；失败可重试。
5. 反复切换应用后无重复监听、重复标题事件和残留沙箱。
6. 菜单管理能创建、编辑不同应用菜单，父节点不跨应用。
7. 普通用户只能看到其有效应用授权和角色菜单。
8. 模板执行同一组核心用例。

## 9. 回退边界

- 路由与加载体验只改微前端宿主和子应用适配层，可独立回退。
- 菜单虚拟分组只改菜单管理展示及菜单树 VO，可独立回退。
- 模板验收不影响现有应用，无需回退生产代码。
